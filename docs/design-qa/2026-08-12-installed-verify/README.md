# Drumroll installed-app verification — 12 August 2026

## Verdict

This is an installed-app audit, not a source audit. I launched the signed, notarized `/Applications/Drumroll.app` without starting a lesson, song, or device test, then restored the initial Songs / Local screen. The bundle reports version `1.2.0`, build `1.2.12`.

The app has several visible pieces of the intended product, but it does **not** yet make the requested at-kit experience true for its owner. Of 31 deduplicated asks: **1 TRUE FOR HIM, 14 PARTLY, 16 FALSE**.

The narrow true item is removal of the fundraiser/support-project feel. It does not rescue the core result: the installed Home screen says the kit is reconnecting, the current saved song checkpoint contains seven misses and no hits, the XP chip declares `411 / 50 XP` with a `1` flame, the Coach is still its own nav destination, and the Yandex tabs contain 243 metadata rows with zero playable songs.

## Method and evidence limits

- Checked the actual installed, signed app and its rendered UI; code and repo were not used to decide a status.
- Read existing profile data only at `~/Library/Application Support/sight-kick/config.json`; no run, setting, song, or profile data was created or changed.
- The owner was in Claude rather than actively practicing before launch. The app was returned to its initial Songs / Local view after capture.
- A visual control can be observed, but physical-kit feel, audio timing, hover sound, pause transport, and post-run navigation cannot be called true without a new real-kit run. Those remain PARTLY rather than being promoted from a screen receipt.

## False outcomes ranked by harm at a real kit

1. **R1 / R8 — input, judgment, and persistence are not trustworthy.** A learner cannot trust any tutor if the Home state is reconnecting and the active song record contains only misses. Fix: trace ten physical DTX strikes from MIDI arrival through mapping, judgement, and checkpoint; block result/XP claims until counts agree.
2. **R4 / R5 / R12 — the tutor can make clean playing feel punitive.** The last actual DTX lesson has 99.24% accuracy but a timing-spread intervention at 50%. Fix: do not slow/rewind for spread alone; intervene only after material errors and make the intervention local to the phrase.
3. **R10 — Flow has no installed user contract or timing proof.** Losing a stable timing reference breaks practice faster than missing a cosmetic feature. Fix: one audio-clock transport, tested at 70% and 100%, with a visible Flow/Classic preflight.
4. **R9 — pad-start is an unproven promise while the kit reconnects.** The wording exists, but the actual hardware state contradicts it. Fix: prove no-mouse start/continue against the DTX before showing the instruction as ready.
5. **R13 / T2 — the product still has the old navigation and no My Wave.** A returning learner lands in a four-tab app with separate Coach rather than a single musical continuation. Fix: Main / My Wave / Songs / Journey; put coaching inside the continuation and lesson decisions.
6. **T1 / R21 / R28 — XP and streak semantics are visibly false.** `411 / 50 XP` plus flame `1` reads as untrusted instrumentation, not motivation. Fix: enforce one display invariant across earned XP, target, streak, and completion; show music evidence first.
7. **R15 — Yandex library is a metadata catalogue, not a practice library.** 243 rows, zero playable. Fix: make only verified local-audio + reviewed-chart rows actionable, then process the library honestly over time.
8. **R22 — stats do not have the requested screen or emphasis.** They are a side drawer. Fix: full-screen post-run stats with a central verified streak and musical trend.
9. **R23 / R25 / R26 — core score controls are absent from the installed experience.** No observed glossary hover, drag loop, or Flow/Classic setting. Fix: implement the interaction trio and run visible acceptance captures.
